# CI Trace 结项说明

## 最终状态

- 作品集演示入口为 `/diagnoses`。公开 GitHub Actions 运行只需链接，即可查看固定轮次、失败 Job 和步骤、检查注释及证据缺口，并下载报告和 JSON 轨迹。首页保留可直接打开的真实失败案例。
- 未结束的运行有独立状态和报告。采集恢复沿用固定轮次，复用已记录的 Job 和验证候选。
- 可选深度分析按 Job 读取受限证据，要求观察和推断引用证据 ID。分析可刷新回放，失败后可显式重试。
- 前端使用 Next.js、React 和 TypeScript。后端使用 FastAPI 和 SQLite，通过 Docker Compose 在本机运行。见 [启动说明](README.md)。
- 独立版已通过 44 项后端回归、容器前端构建、真实公开运行诊断与报告下载。对抗性回归覆盖私有访问拒绝、非法日志重定向、密钥回显、模型地址和响应边界，以及中断后的恢复。模型连接、失败重试和回放用模拟提供商验收。

## 优化方向

1. 用真实模型跑单 Job 和双 Job，保留诊断与模型轨迹，人工核对证据引用、覆盖范围和根因判断。
2. 增加不同运行轮次、日志缺失和 CRLF 的固定对照案例。沿用 `scripts/evaluate_ci_trace.py` 和 `contracts/ci-trace-*.json`。
3. 如需支持私有仓库，单独设计 GitHub 授权、会话隔离和撤权流程，并验证归档与模型访问边界。
